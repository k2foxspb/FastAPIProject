01Обзор

Fokin System — мобильное приложение для общения: друзья, публикации, объявления, новости, личные и групповые чаты, фото и альбомы, ИИ-чат и колокольчик уведомлений. Серверная часть — асинхронный FastAPI-backend, клиент — React Native (Expo).

Backend

FastAPI, SQLAlchemy 2 (async), PostgreSQL, Redis, Celery.

Мобильный клиент

React Native 0.81 и Expo SDK 54 для Android и iOS.

Уведомления

WebSocket в реальном времени и push через Firebase Cloud Messaging.

Веб

Jinja2-страницы: главная, документация, политика, соглашение.

03Push-уведомления

Каждое событие (лайк, комментарий, заявка в друзья, объявление и т.д.) создаёт запись в таблице уведомлений через единую функцию create_or_group_notification() (app/core/notification_service.py). Однотипные события об одном объекте группируются по group_key — счётчик записи растёт, а не создаётся новая строка.

Правила доставки

  • Настройки по группам. Группы: объявления, новости, личные сообщения, групповые чаты, заявки в друзья, новые посты друзей, фото и альбомы. Пользователь может отключить любую, кроме объявлений и системных сообщений.
  • Тихие часы. По умолчанию 22:00–07:00, интервал может переходить через полночь. В это время push доставляется без звука и вибрации (канал silent).
  • Data-only для Android. Сервер отправляет только поле data без блока notification с высоким приоритетом. Иначе Android показал бы системное уведомление, а клиент — второе, своё.
  • iOS. Через APNs уходит alert вместе с data, включены mutable-content и content-available.
  • Аватарка отправителя. Передаётся в sender_avatar; Notifee рисует её в уведомлении на Android, для iOS она передаётся через FCM options.
  • Тег уведомления. notif_tag формируется из типа события (новость, заявка в друзья, чат или отправитель), поэтому новое сообщение заменяет предыдущее из того же диалога.
  • Невалидные токены. Если Firebase сообщает, что токен недействителен, он автоматически сбрасывается у пользователей в базе данных.

Раздельные счётчики

Колокольчик и сообщения считаются независимо: непрочитанные уведомления — через /notifications (unread_count и /notifications/unread-count), непрочитанные сообщения — через поле unread_count в списке диалогов чата. Прочтение одного не влияет на другое.

Пример data-payload

{
  "type": "new_message",
  "notification_group": "chat",
  "notif_title": "Имя отправителя",
  "notif_body": "Текст сообщения",
  "sender_id": "42",
  "sender_avatar": "/media/avatars/...",
  "android_channel_id": "messages",
  "notif_tag": "sender_42",
  "silent": "false"
}

Все значения в data — строки (требование Firebase Admin SDK). Значения выше приведены для иллюстрации.

04Схема потока уведомлений

→ → → → → →

Событие

Роутер (users, feed, news, chat…) фиксирует действие: лайк, комментарий, заявку в друзья, новое объявление.

Роутер вызывает сервис уведомлений, а не работает с моделью напрямую.

Сервис уведомлений

create_or_group_notification() создаёт запись либо увеличивает счётчик существующей непрочитанной записи с тем же group_key.

Тип события сопоставляется с группой настроек.

База данных

Запись сохраняется до доставки: колокольчик показывает историю даже если push не дошёл. Список и счётчик отдаёт notification_center.

Диспетчер

dispatch_notification() проверяет, не отключена ли группа, нет ли у пользователя токена и не наступили ли тихие часы.

Объявления и системные сообщения отправляются всегда. Отправка идёт фоновой задачей и не блокирует запрос.

WebSocket

Если приложение открыто, сообщение типа notification уходит по WebSocket сразу, и колокольчик обновляется без опроса.

FCM / APNs

Firebase Admin SDK отправляет сообщение в Firebase Cloud Messaging.

Android

Data-only, приоритет high, TTL 24 часа.

iOS

Alert + data через APNs, звук отключается в тихие часы.

Клиент

Background handler на @react-native-firebase/messaging принимает data-сообщение, а @notifee/react-native показывает единственное уведомление с аватаркой отправителя в нужном канале (messages или silent).

05Мобильное приложение

Приложение собрано на Expo SDK 54 и React Native 0.81 с React 19.1. Навигация — React Navigation 7 (native-stack и bottom-tabs). Для сетевых запросов используется axios, для локального хранилища — AsyncStorage.

  • Push приходит как data-only сообщение и обрабатывается в фоне, уведомление строит Notifee.
  • Каналы уведомлений: messages (звук) и silent (без звука для тихих часов).
  • В уведомлении показывается аватарка отправителя, повторные сообщения заменяют друг друга по notif_tag.
  • Уведомление формирует APNs: alert, звук (кроме тихих часов), thread-id для группировки по диалогу.
  • Включены mutable-content и content-available, чтобы клиент мог дополнить уведомление.
  • Для действий используется категория message_actions у новых сообщений.

Для проверки подлинности приложения используется Firebase App Check, для входа — Firebase Auth.

08Безопасность

  • Доступ к API — по токену аутентификации, права разграничены ролями.
  • Трафик защищён HTTPS/TLS на уровне nginx.
  • Учётные данные сервисов (в том числе Firebase) хранятся вне репозитория и подключаются через окружение.
  • Недействительные push-токены автоматически удаляются.
  • Файлы отдаются через слой хранения, который проверяет существование и тип.
